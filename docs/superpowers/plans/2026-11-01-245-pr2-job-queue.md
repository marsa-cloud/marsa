# #245 PR 2 — Job queue module (pg-boss) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `src/modules/jobs`: a pg-boss job queue whose jobs are sent only inside a Drizzle
transaction, handlers found by `@JobHandler` discovery, optional per-job cron, workers behind
`JOBS_WORKER_ENABLED`, and a `drainJobs()` test helper. A test-only job proves it works. No
feature uses the queue yet.

**Architecture:** One global `JobQueueModule` (in `AppModule`, like `DatabaseModule`) provides a
`PgBoss` instance (`PG_BOSS` token, `pgboss` schema, same DB URL as Drizzle), a `JobRegistry`
(discovers `@JobHandler` providers through `DiscoveryService.createDecorator`), a
`JobQueueLifecycle` (start → create queues → schedule crons → `work` when enabled; graceful stop
before the Drizzle pool closes) and `JobScheduler.send(tx, job)`, which inserts through
`fromDrizzle(tx, sql)` so the job commits or rolls back with the caller. Tests keep workers off and
run jobs with `drainJobs(app)`, which fetches with `ignoreStartAfter` so retries and dead-lettering
are deterministic.

**Tech Stack:** NestJS 11 (`DiscoveryService`, lifecycle hooks), pg-boss 12.38.0, Drizzle
`1.0.0-rc.4` on `pg`, Joi env schema, `node:test`.

**Spec:** `docs/superpowers/specs/2026-11-01-domain-events-job-queue-design.md` — "Decisions"
(D1, D6), "Components → `src/modules/jobs`", "Error handling" (visibility), "Testing", "Delivery"
row 2. Decision record: `docs/agdr/AgDR-0051-domain-events-and-pg-boss-job-queue.md`.

## Review Focus

1. **A queue whose options change after it exists.** `createQueue` is a no-op on an existing queue,
   so a changed `retryLimit` / `deadLetter` would be silently ignored. `JobScheduler.send` passes
   the class options on every send (Task 3 unit test pins it).
2. **Dead-letter queue created after the queue that references it.** `pgboss.queue.dead_letter` is
   an FK to `pgboss.queue(name)`, so bootstrap must create dead-letter targets first (Task 4
   integration test with a dead-lettering job pins it).
3. **Two classes on one queue, or two handlers for one job.** Bootstrap must throw naming the queue,
   not let the second silently win (Task 2 unit tests).
4. **Sending a job nobody handles in this process.** `send` must throw `No @JobHandler registered for
queue '<name>'` instead of pg-boss's raw "queue does not exist" (Task 3 unit test).
5. **SIGTERM with a job in flight.** `stop({ graceful: true })` must run while the Drizzle pool is
   still open, so the pool now ends in `onApplicationShutdown` and pg-boss stops in
   `beforeApplicationShutdown`; `api.ts` gains `enableShutdownHooks()` (Task 1 + Task 3 unit test on
   the hook).

import type { Queue } from 'pg-boss'

export type JobQueueOptions = Pick<
  Queue,
  | 'retryLimit'
  | 'retryDelay'
  | 'retryBackoff'
  | 'retryDelayMax'
  | 'expireInSeconds'
  | 'deadLetter'

  static readonly queue: string
  static readonly options: JobQueueOptions = {}
  static readonly schedule?: string // cron, registered with boss.schedule
  constructor(readonly payload: TPayload) {}
}

export type JobClass<TPayload extends object = object> = {

**Interfaces:**

- Consumes: `databaseUrl(config)` (Task 1); `JobRegistry`, `JobRegistration`, `JobClass`, `Job`
  (Task 2); `Transaction` from `#src/modules/database/drizzle.factory.js`.
- Produces:
  - `export const PG_BOSS = Symbol('PG_BOSS')`.
  - `createPgBoss(config: ConfigService): PgBoss` —
    `new PgBoss({ connectionString: databaseUrl(config), schema: 'pgboss', supervise: workersEnabled, schedule: workersEnabled })`
    and attaches `boss.on('error', …)` logging through a `Logger('PgBoss')` (an unhandled `'error'`
    event would crash the process). It never connects; `start()` is the lifecycle's job.
  - `@Injectable() class JobScheduler` (injects `PG_BOSS`, `JobRegistry`):
    `send<TPayload extends object>(tx: Transaction, job: Job<TPayload>, overrides?: JobSendOverrides): Promise<string | null>`
    where `export type JobSendOverrides = Omit<SendOptions, 'db'>`. Calls
    `boss.send(queue, job.payload, { ...sendable(options), ...overrides, db: fromDrizzle(tx, sql) })`;
    `sendable` drops `policy` (not a send option). Throws
    `No @JobHandler registered for queue '<queue>'` when `!registry.isRegistered(queue)`. Returns
    pg-boss's id (`null` when a singleton/policy suppressed the job).
  - `@Injectable() class JobQueueLifecycle implements OnApplicationBootstrap, BeforeApplicationShutdown`:
    - `onApplicationBootstrap`: `await boss.start()`; then for each registration in
      `registry.registrations()` order: `createQueue(queue, jobClass.options)`; when
      `jobClass.schedule` is set, `boss.schedule(queue, jobClass.schedule)` (always — schedules are
      cluster-wide rows); when `JOBS_WORKER_ENABLED`, `boss.work(queue, { batchSize: 1 }, ([job]) => this.run(registration, job))`.
    - `run(registration, job)`: awaits `handler.handle(job.data, job)`; on throw logs
      `` `${queue} ${job.id}: ${message}` `` at error level and rethrows.
    - `beforeApplicationShutdown`: `await boss.stop({ graceful: true })`.
  - `@Global() @Module({ imports: [DiscoveryModule], providers: [{ provide: PG_BOSS, inject: [ConfigService], useFactory: createPgBoss }, JobRegistry, JobScheduler, JobQueueLifecycle], exports: [PG_BOSS, JobRegistry, JobScheduler] }) class JobQueueModule`.

### Task 4: `drainJobs()`, teardown, and the test-only job proof

**Files:**

- Create: `apps/api/src/test/jobs/drain-jobs.ts`

**Interfaces:**

- Consumes: `PG_BOSS`, `JobRegistry.registrations()`, `JobScheduler.send` (Task 3); `TestBench.setupModuleTest(module)` and `TestSetup.{app, db, teardown}`.
- Produces:
  - `drainJobs(app: INestApplicationContext): Promise<void>` — passes over
    `registry.registrations()`; per queue, repeatedly `boss.fetch(queue, { batchSize: 1, ignoreStartAfter: true })`
    until empty, running `handler.handle(job.data, job)` then `boss.complete(queue, job.id)`, or on
    throw `boss.fail(queue, job.id, { message })`. Repeats passes until a pass runs nothing, so jobs
    sent by jobs, retries and dead-letter jobs all run. After `MAX_DRAIN_PASSES = 100` passes it
    throws `drainJobs: queues still busy after 100 passes`. Queues without a handler are ignored.
  - `truncateAll` also truncates `pgboss.job` (append `"pgboss"."job"` to the table list; `CASCADE`
    covers `pgboss.job_dependency`). Queue and schedule rows stay: they're created at app bootstrap
    and the test apps are cached across suites.
  - `global-setup.ts` additionally runs `TRUNCATE pgboss.job CASCADE` after `migrate`, so jobs left
    by an aborted earlier run can't leak into the first suite (the context's bootstrap has already
    created the schema).
  - `test-jobs.ts` exports, each with an `@Injectable() @JobHandler(...)` handler that records calls
    in an exported `const calls: Record<string, unknown[]>`, plus `class TestJobsModule` providing
    all handlers:
    - `EchoJob` (`queue: 'test-echo'`) — records payload `{ n: number }`.
    - `ChainJob` (`queue: 'test-chain'`) — handler injects `@InjectDatabase()` + `JobScheduler` and, in a
      `db.transaction`, sends `new EchoJob({ n: payload.n + 1 })`.
    - `FlakyJob` (`queue: 'test-flaky'`, `options: { retryLimit: 3, retryDelay: 60 }`) — throws on
      its first two attempts (`job.retryCount < 2`), then records.
    - `FailingJob` (`queue: 'test-failing'`, `options: { retryLimit: 2, retryDelay: 60, retryBackoff: true, deadLetter: 'test-dead-letter' }`) — always throws `new Error('nope')`.
    - `DeadLetterJob` (`queue: 'test-dead-letter'`) — records payload.
    - `CronJob` (`queue: 'test-cron'`, `schedule: '0 3 * * *'`) — records.
